# 常见故障排查

## 1. 后台打不开

先看服务：

```bash
sudo systemctl status zj-agent-web.service
sudo journalctl -u zj-agent-web.service -n 200
```

常见原因：

- `ADMIN_USERNAME` / `ADMIN_PASSWORD` 没配
- `APP_SECRET_KEY` 没配
- `MYSQL_DSN` 错误
- 端口被占用

## 2. 周任务没执行

看 timer：

```bash
sudo systemctl status zj-agent-weekly.timer
systemctl list-timers | grep zj-agent
```

再看 job：

```bash
sudo journalctl -u zj-agent-weekly.service -n 200
```

## 3. 抓取没有新数据

优先排查：

- 来源是否被后台禁用
- 网站结构是否变化
- 失败队列是否堆积
- `HTTP_TIMEOUT_SECONDS` 是否太低

建议动作：

- 后台页面里对单来源执行 `Inspect`
- 再执行单来源 `Run weekly`
- 查看 `Jobs` 和 `Pending failures`

## 4. AI 提取一直失败

优先检查：

- `LLM_API_KEY`
- `LLM_BASE_URL`
- `LLM_MODEL`
- 模型响应超时

可调参数：

- `LLM_TIMEOUT_SECONDS`
- `LLM_MAX_TOKENS`
- `LLM_CONTENT_CHAR_LIMIT`

## 5. 飞书没有消息

先测：

```bash
export PYTHONPATH=src
.venv/bin/python -m zj_agent.cli notify feishu-test --text "zj-agent test"
```

如果失败，通常是：

- `FEISHU_WEBHOOK_URL` 错
- webhook 失效
- 开了签名但 `FEISHU_SIGN_SECRET` 没配

## 6. 为什么明明有线索但没有推送

当前周推送规则是：

- 只推 `clue_pool`
- 只推最近 `WEEKLY_LOOKBACK_DAYS`
- 必须有 `published_at`
- 只推未推送的数据

所以以下情况不会被推：

- 太老
- 没有发布时间
- 已经推过
- 没进入 `clue_pool`

## 7. 数据库升级后报字段不存在

先执行：

```bash
export PYTHONPATH=src
.venv/bin/python -m zj_agent.cli init-db
```

当前程序会在 `init-db` 时自动补齐兼容字段和 `job_runs` 表。
